# Guía del alumno / Learner guide

## Una sesión útil

Antes de empezar escribe una pregunta: «¿por qué no puedo escribir en esta carpeta?» es mejor objetivo que «leer Windows». Comprueba prerrequisitos. Selecciona el SO adecuado y empieza por los fundamentos si no puedes distinguir cuenta, proceso, archivo y permiso.

Propuesta ajustable: **un ciclo de 25 minutos para entender y otro para practicar y explicar**, separados por una pausa de cinco. No es una duración científica universal ni una obligación del curso. Un concepto sencillo puede necesitar menos; preparar una VM o resolver un fallo nuevo puede requerir una sesión separada. Fija un objetivo razonable, no una carrera contra el contador.

## Secuencia de una lección

Pregunta y resultado esperado → concepto → micropráctica de explicación → siguiente concepto → esquema → ejemplo comentado → preparación del entorno → un paso de práctica cada vez → autoevaluación → evidencia → recuperación → entrega.

No copies primero toda la solución. Predice, ejecuta un paso y contrasta. Si el resultado difiere, registra el contexto antes de cambiarlo. Un error de permiso puede demostrar que el control funciona; no lo elimines solo para ver una salida correcta.

## Qué significan tus marcas

**Comprobado:** has contrastado ese punto; es tu declaración. **Necesito repasar:** no puedes explicarlo o la respuesta fue incorrecta. **Bloqueo de entorno:** falta SO, licencia, herramienta o permiso. No es equivalente a ausencia de conocimiento y no cuenta como completado. Una práctica nativa requiere confirmación específica; desde una tableta puedes estudiar y predecir, pero no atribuirte su ejecución.

Para profundizar utiliza las fuentes de la lección y los módulos antiguos enlazados conceptualmente. No necesitas recorrer la biblioteca entera antes de realizar una práctica pequeña. Vuelve al día siguiente a explicar un concepto sin mirar; si no puedes, márcalo para repaso. Esto es una pauta docente, no un calendario adaptativo implementado.

## Resolver problemas con método

| Paso | Pregunta |
|---|---|
| Definir | ¿Qué esperaba y qué observé, exactamente? |
| Acotar | ¿En qué host, SO, versión, shell, identidad y ruta? |
| Formular | ¿Qué dos causas podrían explicar el resultado? |
| Discriminar | ¿Qué comprobación pequeña y autorizada separa esas hipótesis? |
| Comprobar | ¿Qué salió y qué conclusión NO puedo extraer todavía? |
| Decidir | ¿Corrijo, revierto, recopilo otra evidencia o pido ayuda? |

Tras varios intentos sin información nueva, no repitas más deprisa. Abre una pista, consulta ayuda oficial o prepara una pregunta reproducible. Anota lo probado y evita repetir operaciones destructivas. Si aparece información real no prevista o un efecto fuera del alcance, detente y avisa.

## Cambiar de equipo

Comparte la URL para abrir el mismo punto y lenguaje. Exporta/importa el JSON del aula para trasladar sus marcas y tiempos. Exportar no sincroniza cambios futuros; guarda la copia en un lugar apropiado y no la confundas con el registro del campus general. Las notas del problema se descargan aparte; no se incluyen en la copia de progreso.

En Apple Silicon no supongas que una imagen x86 funciona por instalar VirtualBox/Fusion. Usa una imagen y un hipervisor compatibles o un laboratorio docente asignado. El asistente **Mi entorno** ofrece un itinerario y descargas oficiales. No desactiva requisitos ni instala nada automáticamente.

## Aprender a comunicar

Entrega en cinco líneas: objetivo, resultado, evidencia, limitación y siguiente acción. Para una decisión de cambio, compara alternativas con esfuerzo, impacto y reversibilidad. No inventes métricas. Cambia «he instalado la herramienta» por «el usuario previsto puede leer y el no autorizado recibe denegación, comprobado de esta manera».

## English

Choose a concrete question and check prerequisites. Start with shared foundations, then follow your OS path. Use an optional 25-minute focus interval followed by a manually started break. Predict before revealing a solution; perform one lab step and compare expected/observed results. Revisit unclear points instead of treating time spent as mastery.

When stuck, record context, two hypotheses, one safe discriminating test and its result. Stop if permission, platform or scope is missing. Ask for help with a reproducible example and sanitized evidence. Share the lesson URL; export/import the OS JSON record to carry marks to another device. Native practice and read-only simulation are different achievements.

Finish with an actionable handover: objective, outcome, evidence, limitation and next step. For decisions, compare effort, impact and reversibility without inventing effectiveness or savings.
