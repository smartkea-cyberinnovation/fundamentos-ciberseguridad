# Cómo estudiar: teoría, práctica y evidencia

## Primer contacto

Abre el índice completo del campus y localiza M01. Sin experiencia en terminal, realiza M01–M04 antes de empezar Linux. Un error en una práctica es un dato para diagnosticar: no una razón para conceder permisos administrativos generales.

La web es el cuaderno y la guía. Los comandos se ejecutan manualmente en máquinas del laboratorio. Una máquina virtual y un contenedor no son equivalentes; tampoco PowerShell sobre Linux sustituye la administración nativa de Windows.

## La secuencia de cada módulo

1. Lee la entrada, los prerrequisitos y el resultado esperado.
2. Estudia el mecanismo y compruébalo mediante una consulta pequeña.
3. Resuelve la autoevaluación y explica por qué descartas las otras opciones.
4. Completa las prácticas A, B y C, documentando resultados y errores.
5. Explica una comprobación positiva, una negativa y una limitación.

## Las cinco fases de una práctica

| Fase | Qué haces | Evidencia mínima |
|---|---|---|
| Preparar | Identificar host, versión, cuenta, alcance y recuperación | Ficha de entorno |
| Ejecutar | Leer y comprender cada comando; usar solo el laboratorio | Registro de pasos |
| Comprobar | Contrastar con otra observación y distinguir error de ausencia | Resultado esperado/observado |
| Documentar | Conservar originales, hashes cuando proceda y límites | Informe sin secretos |
| Recuperar | Revertir lo temporal o probar restauración según la ficha | Verificación final |

Marcar una fase confirma tu declaración, no una ejecución observada por el campus. Las guías R01–R08 amplían una selección de las 96 fichas; las restantes requieren la preparación indicada por el docente.

## Leer y presentar

En teoría, usa el índice interno y el botón de texto ampliado. El modo presentación sirve para exponer la misma lección: flechas para avanzar y Escape para cerrar. Los bloques largos se desplazan. La lectura continua permite consultar e imprimir sin JavaScript; no guarda progreso.

## Elegir una ruta

**Base común:** M01–M04. **Administración Linux:** M05–M12. **Windows:** M13–M19. **macOS:** M20–M23. **Operación, Blue Team, DFIR y CTI:** M24–M30, tras sus prerrequisitos. **IA supervisada:** M31. **Integración y defensa:** M32.

Las rutas abreviadas de 60, 120 y 240 horas están en [el plan docente](PLAN-DOCENTE.md); no equivalen a completar las 480 horas. Para comparar herramientas consulta [las equivalencias](REFERENCIA-CRUZADA.md). Para preparar las máquinas consulta [el laboratorio](LABORATORIO.md).

## Conservar el trabajo

Las notas y marcas viven en localStorage del origen web. Exporta tu JSON desde Mi recorrido antes de cambiar de dominio, navegador, dispositivo o limpiar datos. Importarlo reemplaza tu copia local con confirmación. No es un sistema colaborativo: evita editar el mismo módulo simultáneamente en dos pestañas.

No pegues tokens, contraseñas, expedientes ni registros reales. Las notas y el JSON no están cifrados. El porcentaje refleja hitos autodeclarados, no asistencia, tiempo medido ni certificación.

## Desbloquearse sin perder el método

Ante un fallo, anota el mensaje completo, el comando sin secretos, el directorio, el usuario y la versión. Verifica ruta, sintaxis, permiso, red y servicio según la hipótesis. Consulta la ayuda nativa. No desactives controles para conseguir una captura de éxito.

La IA puede ayudar a explicar datos sintéticos o revisar una propuesta, pero no es una autoridad ni ejecuta acciones desde este campus. Toda modificación necesita comprensión, prueba y recuperación.
